## Test-driven development

Write the test first, and see it fail, then write the code. Skip a test only when it would be
expensive, integration-heavy, or unclear. Use the closest real check in its place. A skip is never
silent: say that you skipped, and give the reason.

## Comments

No comments. Two exceptions: tool directives and comments that lint requires.
