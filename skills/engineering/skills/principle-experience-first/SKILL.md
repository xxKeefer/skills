# Experience First

When implementation convenience conflicts with user delight, choose delight.

- Justify every feature, control, and option.
- Ship less and ship better. Three polished features beat ten rough ones.
- Prototype before you commit. A design decision costs less in throwaway HTML than in production code.
- Get the details right: transitions, alignment, spacing, feedback, and error states.
- Tighten the core loop. Each feature serves the central workflow or stays out of its way.

The user is whoever consumes the work. For a UI, that is the end user. For a library or an internal API, that is the colleague who imports it. The engineer who maintains the code next is also a user. Weigh their experience the same way, and explain the impact from their view.

Foundations serve the experience. Foundational thinking governs the sequence of work. This principle governs the target.
